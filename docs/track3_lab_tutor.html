1. Bài toán và bản đồ codebase

Bạn đang xây một agent xử lý câu hỏi hỗ trợ. Agent không chỉ gọi LLM một lần: nó phải phân loại ý định, chọn nhánh, gọi tool mô phỏng, đánh giá kết quả, retry có giới hạn, xin phê duyệt cho hành động rủi ro và ghi audit trail.

2. Kiến thức cần nắm

LangGraph khác gì một chain tuyến tính?

Chain thường là A → B → C. LangGraph là state machine: node đọc state và trả về một phần state; graph merge phần trả về bằng reducer; conditional edge chọn nhánh dựa trên state. Vì vậy graph biểu diễn tốt retry loop, approval và nhiều đường kết thúc.

State và reducer

NhómVí dụCách mergeÝ nghĩa
Overwriteroute, attempt, final_answerGiá trị mới thay giá trị cũTrạng thái hiện tại
Append-onlymessages, tool_results, errors, eventsAnnotated[list, add]Lịch sử hội thoại, tool và audit; không làm mất bằng chứng retry
Structuredapproval, classificationDict/Pydantic serializableDễ checkpoint và kiểm thử

Nguyên tắc node: không mutate input state; chỉ return partial update. Mọi node nên ghi một make_event(...) để metrics biết node nào đã chạy.

Structured output

Tạo Pydantic model cho classification, ví dụ route chỉ nhận một trong năm giá trị simple | tool | missing_info | risky | error. Gọi get_llm().with_structured_output(Model).invoke(prompt). Prompt phải nêu định nghĩa route và thứ tự ưu tiên: risky > tool > missing_info > error > simple.

Retry và termination

evaluate là gate: nếu kết quả mới nhất chứa lỗi thì needs_retry, ngược lại success. retry tăng attempt; nếu attempt < max_attempts quay lại tool, nếu không đi dead letter. Đây là rào chắn bắt buộc để graph không loop vô hạn.

HITL và persistence

Nhánh risky phải tạo proposed_action rồi chạy approval trước khi tool thực hiện side effect. Bản cơ bản mock approved=True để CI chạy; extension dùng interrupt(). Checkpointer lưu state theo thread_id, cho phép xem lịch sử hoặc resume sau sự cố.

3. Luồng graph mục tiêu

Sơ đồ trực quan hóa logic trong graph.py; conditional edges có path map tường minh để Mermaid và runtime cùng phản ánh các nhánh.

5. Hướng dẫn triển khai từng bước

Bước 0 — Cài môi trường

python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
pip install -e ".[google]"   # hoặc [openai], [anthropic]
# đặt GEMINI_API_KEY / OPENAI_API_KEY / ANTHROPIC_API_KEY trong .env

Factory trong llm.py chọn Gemini trước, sau đó OpenAI, rồi Anthropic; model có thể override bằng LLM_MODEL.

Bước 1 — Hoàn thiện state.py

Thêm các field mà node/routing sẽ đọc: evaluation_result, pending_question, proposed_action, approval. Khởi tạo chúng trong initial_state nếu muốn state rõ ràng. Giữ mọi giá trị serializable; ApprovalDecision có thể dump thành dict khi trả về.

Bước 2 — Viết nodes.py theo hợp đồng

  1. classify: gọi LLM structured output; ghi route, risk_level, event. Không dùng scenario ID.
  2. tool: lấy attempt. Với route error và attempt < 2, append chuỗi có ERROR; các trường hợp khác append mock success.
  3. evaluate: đọc result cuối; set needs_retry nếu lỗi, ngược lại success. Có thể nâng điểm bằng LLM-as-judge.
  4. answer: gọi LLM với query, tool_results, approval; yêu cầu chỉ dùng context được cung cấp.
  5. clarify: tạo câu hỏi cụ thể và gán cả pending_question lẫn final_answer.
  6. risky_action: mô tả hành động và lý do cần reviewer.
  7. approval: mock approved mặc định; nếu bật interrupt thì pause và resume bằng quyết định reviewer.
  8. retry: tăng attempt đúng một lần, append error/event.
  9. dead_letter: thông báo không thể xử lý sau max attempts.
  10. finalize: luôn append event finalize/completed.

Bước 3 — Hoàn thiện routing.py

Dùng mapping rõ ràng cho classify; evaluate chỉ cần phân biệt needs_retry; retry so sánh số nguyên; approval đọc approval.approved. Unknown route mặc định sang answer theo test có sẵn.

Bước 4 — Dựng graph.py

Tạo StateGraph(AgentState), register đủ 11 node, thêm fixed edges và add_conditional_edges cho 4 hàm routing. Compile bằng graph.compile(checkpointer=checkpointer). Kiểm tra mọi nhánh đều tới finalize rồi END.

Bước 5 — Persistence

MemorySaver đủ để chạy test. Để làm extension, cài langgraph-checkpoint-sqlite, tạo SQLite connection, bật WAL và dùng SqliteSaver(conn=...). CLI đã truyền thread_id qua configurable; hãy ghi lại state history hoặc demo restart/resume.

Bước 6 — Metrics và report

metric_from_state đếm event node, retry, approval và kiểm tra route + output. summarize_metrics tạo MetricsReport. Implement render_report theo template: summary, từng scenario, kiến trúc, failure analysis và improvement plan.

Checklist debug theo thứ tự

Lỗi thường gặp

  • Không có API key hoặc thiếu package provider.
  • LLM trả route ngoài enum vì prompt/model không structured.
  • Reducer overwrite events khiến metrics đếm thiếu node.
  • Nhầm attempt: kiểm tra giới hạn sau khi tăng.

Cách kiểm tra hành vi

  • simple: reset password
  • tool: order status
  • missing: “Can you fix it?”
  • risky: refund/delete account
  • error: timeout; S07 phải dead-letter
